排序算法

Sorting

💡 为什么学排序？

数据有序后查找只需 O(log n)。排序是二分、去重、贪心等几乎所有操作的前提。竞赛中直接用 sort()，手写主要用于理解分治思想和统计逆序对。

📖 核心思想

快速排序：选 pivot，小的放左大的放右，递归处理。归并排序：分半递归排好再合并，合并时可顺手统计逆序对——这是竞赛高频考点。

sort(begin,end)O(n log n)Introsort 混合排序，不会退化到 O(n²)
手写快排O(n log n) 均摊最坏 O(n²)，但 std::sort() 不会
归并排序O(n log n)稳定排序，可求逆序对，需 O(n) 辅助空间
逆序对统计O(n log n)归并过程中顺便统计：cnt+=mid-i+1

🔬 从零开始理解：排序算法

🎯 生活类比：整理扑克牌

你左手拿一堆乱序的牌，右手一张张抽出来插入左手已排好的位置 — 这是插入排序 O(n²)。
快速排序更像分拣：选一张"基准牌(pivot)"，比它小的放左边、大的放右边，左右各自递归处理——这就是分治(Divide & Conquer)思想。

📐 图解原理

✍️ 手把手做题

题目：数组 [3, 1, 4, 2]，求逆序对个数（i<j 但 a[i]>a[j]）。

第一步 — 暴力法：两重循环枚举所有 (i,j) pair，O(n²)。n=10⁵ 时必超时。

第二步 — 关键洞察：归并排序合并两个已排序子数组时，若左边 a[i] > 右边 a[j]，则左边 a[i] 及其后面所有元素 都 > a[j]（因为左边已排序）→ 一次贡献 mid-i+1 个逆序对！

第三步 — 具体演示：合并 [3,4] 和 [1,2]。i=0指向3，j=0指向1：3>1→贡献 2-0+1=2 对[(3,1)(4,1)]。j++指向2：3>2→再贡献 2 对。总共 4 对。

💡 一句精髓：if (a[i] > a[j]) inv += (mid - i + 1);

❌ 错误1：每次选第一个元素做 pivot → 已排序数组退化为 O(n²)
→ ✅ 随机选 pivot 或取中间。直接用 std::sort() 最安全（Introsort 保证 O(n log n)）。

❌ 错误2：逆序对用 int 存储 → n=10⁵ 时最多 ~5×10⁹ 对，int 溢出！
→ ✅ 必须使用 long long。

❌ 错误3：归并后忘记写回原数组 → 合并完必须 a[l+i]=tmp[i] 写回。

二分查找 & 二分答案

Binary Search

💡 为什么需要二分？

在有序序列中找东西，每次砍掉一半搜索范围，O(log n)。n=10⁹ 只需约 30 次比较。二分答案：当问题有单调性时，对答案值域二分，把"求最优解"变成"判断可行性"。

📖 边界处理与死循环陷阱

整数二分最易出错的是死循环。记住口诀：r=mid 用下取整 (l+r)/2，l=mid 必须上取整 (l+r+1)/2。最安全的方法是用 ans 变量单独记录可行解。

操作复杂度说明
lower_bound()O(log n)找第一个 ≥x 的位置
upper_bound()O(log n)找第一个 >x 的位置
binary_search()O(log n)判断元素是否存在于有序序列
二分答案 + check()O(log 值域 × check)答案满足单调性时使用

🔬 从零开始理解：二分查找 & 二分答案

🎯 生活类比：猜数字游戏

A 心里想一个 1~100 的数，B 来猜。B 每次猜中间数（50），A 说"大了"或"小了"。B 根据反馈每次砍掉一半范围——7 次以内必猜中。这就是二分查找：在有序序列中每次排除一半。

二分答案是更高级的用法：当问题的"答案"满足单调性（答案越大越容易/越难满足条件），就对答案值域二分，把"求最优解"变成"判断可行性"。

📐 图解原理

✍️ 手把手做题

题目（洛谷 P1873）：有 N 棵树，第 i 棵高 H[i]。设置锯子高度 h，能获得 Σ max(0, H[i]-h) 的木材。问至少获得 M 米木材时，h 最大是多少？

关键观察 — 单调性：h 越小 → 获得的木材越多。h 越大 → 木材越少。即 check(h) = "能否获得 ≥M 米木材" 对 h 满足单调性（h 越小越容易满足）。因此可以对 h 做二分！

二分答案步骤：① 确定答案范围 [0, max(H)]；② while(l<r){ mid=(l+r+1)/2; if(check(mid)) l=mid; else r=mid-1; }；③ 答案=l。

⚠️ 为什么要上取整？当 check(mid)=true 时 l=mid，若 mid=(l+r)/2 下取整，当 l+1=r 时 mid=l，l=mid 不变 → 死循环！所以必须 mid=(l+r+1)/2 上取整。

💡 口诀：r=mid→下取整；l=mid→上取整。不放心就用 ans 变量单独记录。

❌ 错误1：死循环 → l=mid 时用了下取整，导致区间不再缩小
→ ✅ r=mid 用 (l+r)/2；l=mid 用 (l+r+1)/2。

❌ 错误2：循环条件写成 l<=r → 当 l=r 时 mid=l=r，若 check=true 则 l=mid 不变，无限循环。
→ ✅ 整数二分用 while(l<r)，退出时 l=r 即答案。

❌ 错误3：check 函数写错单调方向 → 二分答案要求单调性，确保"答案增大→check从true变false"（或反之）。

前缀和 & 差分

Prefix Sum

💡 解决什么问题？

反复查询区间和→每次 O(n) 太慢。前缀和一次 O(n) 预处理，每次查询 O(1)。反过来，反复做区间加法→差分 O(1) 标记两个端点，最后统一 O(n) 还原。两者互为逆运算。

📖 核心公式

一维前缀和：pref[i] = 前 i 项和，sum[l,r] = pref[r+1]-pref[l]。二维：容斥原理，矩形和 = 大矩形 - 上 - 左 + 左上。差分：diff[l]+=x, diff[r+1]-=x。

操作复杂度说明
一维前缀和O(n) 预处理 / O(1) 查询sum[l..r] = pref[r+1] - pref[l]
二维前缀和O(nm) 预处理 / O(1) 查询矩阵和 = 容斥原理
一维差分O(1) 修改 / O(n) 还原区间[l,r]+x 只需改两个端点
二维差分O(1) 修改 / O(nm) 还原矩阵区域统一加减

🔬 从零开始理解：前缀和 & 差分

🎯 生活类比：记账本

你每天都有消费记录。月底想看第 5 天到第 15 天总共花了多少钱——每次都翻账本加一遍？太慢了。前缀和就是累计余额：pref[i] = 前 i 天的总和。查询任意区间和 = pref[r+1] - pref[l]，O(1) 搞定！

差分是前缀和的逆运算：老板说"第5到第15天每天加工资100块"——不用每天改，只需在 diff[5]+=100, diff[16]-=100，最后统一还原。

📐 图解原理

✍️ 手把手做题

场景：给你长度为 n 的数组，q 次查询，每次问区间 [l, r] 的和。n, q ≤ 10⁵。

暴力法：每次查询遍历 [l, r] 求和 → O(nq)，最坏 10¹⁰ 次操作，必超时。

前缀和解法：① 预处理 pre[i] = pre[i-1] + a[i]（O(n)）；② 查询 sum[l..r] = pre[r] - pre[l-1]（O(1)）。总复杂度 O(n+q)。

二维前缀和（子矩阵和）：pre[i][j] = pre[i-1][j] + pre[i][j-1] - pre[i-1][j-1] + a[i][j]。查询 (x1,y1) 到 (x2,y2) 的和 = pre[x2][y2] - pre[x1-1][y2] - pre[x2][y1-1] + pre[x1-1][y1-1]。容斥原理：大矩形 - 上 - 左 + 左上。

❌ 错误1：下标搞混 → 前缀和数组通常开 n+1 大小，pref[0]=0，查询 sum[l..r]=pref[r+1]-pref[l]。
→ ✅ 统一用 0-indexed 或统一用 1-indexed，千万别混用。

❌ 错误2：差分还原时忘记累加 → diff[i] 存的是差值，还原时 a[i] = a[i-1] + diff[i]（不是直接用 diff）。

❌ 错误3：二维容斥符号搞反 → 记住公式：S = 大 - 上 - 左 + 左上（左上被减了两次，要加回来）。

双指针 & 滑动窗口

Two Pointers

💡 为什么需要双指针？

很多问题暴力是 O(n²) 两层循环。但若发现指针只进不退，可用双指针优化到 O(n)——每个元素最多被左右指针各访问一次。

📖 三种经典模式

对撞指针：两端往中间走（有序数组两数之和）。快慢指针：一快一慢去重。滑动窗口：维护 [l,r] 可变窗口，右扩满足条件，左缩打破条件。

操作复杂度说明
滑动窗口O(n)右指针扩张 + 左指针收缩
对撞指针O(n)有序数组的两端向中间移动
快慢指针O(n)数组原地去重、链表判环

🔬 从零开始理解：双指针 & 滑动窗口

🎯 生活类比：伸缩的窗户

想象一个可以伸缩的窗户在数组上滑动。窗口右端向右扩张（加元素），窗口左端向右收缩（减元素）。维护窗口内的某些统计信息（如和、最大值、元素种类数），在窗口滑动过程中找到满足条件的最优解。

双指针更广义：两个指针 i 和 j，通常 i 向右移时 j 也"单调"地向某个方向移动——利用这种单调性将 O(n²) 降到 O(n)。

📐 图解原理

✍️ 手把手做题

题目：给定字符串 s，找出不含重复字符的最长子串的长度。如 "abcabcbb" → 答案 3 ("abc")。

滑动窗口思路：

  1. 维护窗口 [l, r]，窗口内始终无重复字符。
  2. r 不断右移，将 s[r] 加入窗口。如果 s[r] 已在窗口中 → l 右移直到窗口内不再有重复。
  3. 每步用 r-l+1 更新最大长度。

演示：s = "abcabcbb"。l=0,r=0→"a"；r=1→"ab"；r=2→"abc"（长度3）。r=3时 s[3]='a' 已存在 → l 移到第一个 a 后面→窗口变"bca"（长度3）...

💡 复杂度：l 和 r 各自最多移动 n 次 → O(n)。每步 O(1) 用哈希表判断重复。

❌ 错误1：忘记移动左指针 → 窗口只扩张不收缩，导致结果偏大。
→ ✅ 遇到冲突时必须移动 l 直到合法。

❌ 错误2：双指针写成 O(n²) → 每次 r 右移时 l 又从头开始扫。
→ ✅ 关键：l 只向右移动，永不回退。每个元素最多被访问两次。

基础数论

Number Theory

💡 解决什么问题？

GCD/LCM：约分、判断互质。快速幂：a^n mod m 从 O(n) 优化到 O(log n)。素数筛：预处理 [1,n] 内所有素数。竞赛中数论题很常见，掌握基础就能解决不少问题。

📖 核心公式与原理

欧几里得：gcd(a,b)=gcd(b,a%b)，直到 b=0。快速幂：二进制拆分指数，n 的二进制有 log₂n 位。关键是 if(n&1)res=res*a%mod 和 a=a*a%mod。

操作复杂度说明
gcd(a,b)O(log min(a,b))辗转相除法
lcm(a,b)O(log min(a,b))a/gcd(a,b)*b，先除后乘防溢出
快速幂 a^n mod mO(log n)二进制拆分指数
欧拉筛O(n)每个合数只被最小质因子筛掉
C++
int gcd(int a,int b){return b?gcd(b,a%b):a;}
int lcm(int a,int b){return a/gcd(a,b)*b;}

  while(n){if(n&1)res=res*a%mod;a=a*a%mod;n>>=1;}
  return res;

🔬 从零开始理解：基础数论

🎯 生活类比：切蛋糕与公约数

两个人分蛋糕，要切成大小相同的块，每块尽可能大——这就是最大公约数 (GCD)。切成整数块的最小总块数——这涉及最小公倍数 (LCM)。

而素数筛就像在名单上逐个划掉合数：2 是素数，划掉 4,6,8,...；3 是素数，划掉 6,9,12,...；剩下的就是素数。

📐 图解原理

✍️ 手把手做题

GCD 模板（一行）：int gcd(int a,int b){return b?gcd(b,a%b):a;}

LCM：lcm(a,b) = a / gcd(a,b) * b（先除后乘防溢出）。

快速幂：求 a^b mod m。核心：b 的二进制拆分。a^13 = a^(1101₂) = a^8 · a^4 · a^1。每次 a=a*a%m（翻倍），b>>=1（右移），b&1 时 ans=ans*a%m。O(log b)。

埃氏筛（Eratosthenes）：求 [1..n] 所有素数。从 2 开始，每找到一个素数 p，就把 p 的所有倍数标记为合数。O(n log log n)。优化：从 p² 开始标记（更小的倍数已被筛过）。

💡 应用场景：模运算求逆元、分数约分、组合数取模、区间素数判定。

❌ 错误1：LCM 写成 a*b/gcd(a,b) → a*b 可能溢出！
→ ✅ 先除后乘：a/gcd(a,b)*b。

❌ 错误2：快速幂忘记取模 → a 和 ans 每次乘法后都要取模，否则中途溢出。
→ ✅ a = 1LL * a * a % mod;

❌ 错误3：筛法数组开太小或忘记初始化 → isPrime[0]=isPrime[1]=false。

贪心算法

Greedy

💡 什么是贪心？

每步都选当前看起来最好的选项，不回溯。不能保证所有问题的最优解，但在区间调度、哈夫曼编码等问题上可以证明是最优的。

📖 经典模式与证明

区间调度：按结束时间排序，每次选最早结束的→用交换论证可证最优。哈夫曼树：每次合并最小的两堆→用小根堆维护。部分背包：按性价比排序。

操作复杂度说明
区间调度O(n log n)按结束时间排序，贪心选不冲突的
哈夫曼编码O(n log n)小根堆每次取最小两堆合并
部分背包O(n log n)按性价比（价值/重量）排序

🔬 从零开始理解：贪心算法

🎯 生活类比：找零钱

假设你有 1 元、5 元、10 元硬币，要找零 18 元。你会怎么做？先拿最大的 10 元（剩 8），再拿 5 元（剩 3），再拿 3 个 1 元——总共 5 个硬币。这就是贪心：每一步都做当前看起来最优的选择，不回溯。

⚠️ 注意：贪心只在问题满足贪心选择性质时正确（局部最优→全局最优）。不是所有问题都能贪心！

📐 图解原理

✍️ 手把手做题

题目：给 n 个区间 [lᵢ, rᵢ]，选最少的点使得每个区间至少包含一个点。

贪心策略：① 按右端点 rᵢ 从小到大排序；② 从前往后扫描，若当前区间未被覆盖 → 在它的右端点放一个点（这是能覆盖当前区间的最靠右位置，最可能也覆盖后续区间）。

为什么正确？右端点最小的区间必须被覆盖，而把点放在它的右端点是最"慷慨"的选择——给后面的区间留下最大的覆盖机会。

步骤：sort(按 r) → last = -INF → for each [l,r]: if l > last: ans++, last = r。

💡 贪心通用思路：排序→按序处理→维护当前状态→判断是否选当前元素。

❌ 错误1：不证明就贪心 → 不是所有问题都能贪心！如果贪心策略不对，样例都过不了。
→ ✅ 先想反例：是否存在"当前最优选择"导致全局变差的情况？

❌ 错误2：排序关键字选错 → 活动选择按"开始时间"排序是错的！
→ ✅ 正确是按"结束时间"排序。排序前先想清楚为什么这样排。

Graph Search

💡 解决什么问题？

图/树遍历、找所有可能解、找最短路径。DFS 用递归/栈一条路走到底再回溯。BFS 用队列一层层扩展，第一次到达即最短路（边权=1时）。

🎯 生活类比：探索迷宫

📐 图解原理

✍️ 手把手做题

题目：给定 n，输出 1~n 的所有排列（全排列）。如 n=3 → 123, 132, 213, 231, 312, 321。

DFS 回溯思路：

  1. 状态表示：path[i] = 第 i 个位置选了什么数；used[x] = 数 x 是否已用过。
  2. dfs(depth)：已选 depth 个数。若 depth==n → 输出 path，返回。
  3. 否则枚举 1~n 中未使用的数 x：path[depth]=x, used[x]=true, dfs(depth+1), used[x]=false（回溯！）

BFS 求迷宫最短路：从起点入队→每次取队首→四个方向探索→未访问过的合法位置入队并标记距离。第一次到达终点时的距离就是最短距离。

💡 DFS vs BFS：DFS 找所有解（回溯）；BFS 找最短路径（无权图最短路）。DFS 用递归（简洁），BFS 用队列。

❌ 错误1：DFS 忘记回溯恢复状态 → used[x]=true 后必须 used[x]=false 恢复，否则后续分支看不到 x。
→ ✅ 递归调用后对称地恢复现场。

❌ 错误2：BFS 忘记标记访问 → 同一位置多次入队导致 MLE/TLE。
→ ✅ 入队时立刻标记 visited，不要在出队时才标记。

❌ 错误3：DFS 递归太深爆栈 → 递归深度 >10⁶ 可能栈溢出。
→ ✅ 预估深度或用迭代栈。

动态规划 (DP)

DP

💡 什么是 DP？

把大问题拆成重叠的子问题，用数组记住子问题答案避免重复计算。本质是空间换时间。斐波那契 f[n]=f[n-1]+f[n-2] 就是最简单的 DP。

① 定义状态：dp[i] 表示什么？② 转移方程：怎么从前面推出来？③ 初始化：边界值。④ 遍历顺序：从小到大还是倒序？⑤ 返回答案：dp[n]？max(dp)？

最长公共子序列 LCSO(nm)排列 LCS 可转 LIS 优化
编辑距离O(nm)增/删/改三种操作的最小次数

🔬 从零开始理解：动态规划 (DP)

🎯 生活类比：爬楼梯

你站在第 0 级台阶。每次可以走 1 或 2 级。走到第 n 级有几种走法？

如果走到第 3 级：可以从第 1 级走 2 步上来，或从第 2 级走 1 步上来 → f(3)=f(2)+f(1)。
这个递推关系就是 DP 的核心：大问题拆成小问题，小问题结果被重复利用。关键要素：状态定义 + 状态转移方程 + 边界条件。

📐 图解原理

✍️ 手把手做题

题目：给定数组 a，求连续子数组的最大和。如 [-2, 1, -3, 4, -1, 2, 1, -5, 4] → 答案 6（子数组 [4, -1, 2, 1]）。

DP 分析：① 状态定义：dp[i] = 以 a[i] 结尾的最大子数组和。② 转移方程：dp[i] = max(dp[i-1] + a[i], a[i])（要么接在前面的子数组后面，要么另起炉灶）。③ 边界：dp[0] = a[0]。④ 答案：max(dp[0..n-1])。

追踪演示：a=[-2,1,-3,4,-1,2,1]。dp[0]=-2；dp[1]=max(1, -2+1)=1；dp[2]=max(-3,1-3)=-2；dp[3]=max(4,-2+4)=4；dp[4]=max(-1,4-1)=3；dp[5]=max(2,3+2)=5；dp[6]=max(1,5+1)=6。

💡 空间优化：dp[i] 只依赖 dp[i-1]，可以用一个变量滚动更新，O(n) 时间 O(1) 空间。

❌ 错误1：状态定义不清楚 → DP 最关键的步骤！想清楚"dp[i] 代表什么"才能写出转移方程。
→ ✅ 通常定义为"以 i 结尾的...的最优值"或"前 i 个...的最优值"。

❌ 错误2：忘记初始化边界 → dp[0] 或 dp 初始值没设置正确，全盘皆错。
→ ✅ 先写边界，再写循环。

❌ 错误3：遍历顺序错误 → 有些 DP 需要按特定顺序填充（如区间 DP 按长度枚举）。

🔬 从零开始理解：背包问题

🎯 生活类比：旅行打包

你有一个容量有限的背包（比如 10kg），有 n 件物品，每件有重量 w[i] 和价值 v[i]。你要选一些装进去，在不超过背包容量的前提下，让总价值最大。

📐 图解原理

✍️ 手把手做题

问题：n 件物品，容量 C。第 i 件重量 w[i]，价值 v[i]。每件最多选一次，求最大价值。

状态定义：dp[i][j] = 考虑前 i 件物品，容量为 j 时的最大价值。

转移方程：对第 i 件物品，有两种选择：不选→dp[i-1][j]；选→dp[i-1][j-w[i]] + v[i]（前提 j≥w[i]）。取 max。

一维优化（关键！）：dp[j] = max(dp[j], dp[j-w[i]]+v[i])。注意！j 必须从大到小遍历，否则一件物品可能被选多次（变成完全背包）。从小到大的遍历恰好是完全背包的写法。

💡 口诀：0/1 背包→j 从大到小；完全背包→j 从小到大。一维 dp 省空间，O(nC) 时间。

❌ 错误1：一维优化时 j 从小到大循环 → 导致每件物品被多次使用（变成完全背包）。
→ ✅ 0/1 背包必须 for(j=C; j>=w[i]; j--)。

❌ 错误2：dp 数组初始化错误 → "恰好装满"→dp[0]=0, 其余=-INF；"不超过容量"→全 0。
→ ✅ 根据问题要求选择初始化方式。

并查集 (DSU)

💡 解决什么问题？

动态维护集合的合并与查询："两个元素在同一集合吗？""合并这两个集合"。暴力 O(n)，并查集近乎 O(1)——路径压缩+按秩合并后均摊≈O(α(n))≈常数。

🔬 从零开始理解：并查集 (DSU)

🎯 生活类比：家族树

一群人，每个人最初只认识自己。慢慢地，有人告诉你"A 和 B 是一家人"。你需要快速回答"X 和 Y 是不是一家人？"

📐 图解原理

✍️ 手把手做题

题目：给一张图，每次加一条边 (u,v)，问当前有多少个连通块（或问 u,v 是否已连通）。

DSU 解法：① 初始 n 个点各自独立，连通块数 = n。② 加边 (u,v)：若 find(u) ≠ find(v) → union(u,v)，连通块数 -1。③ 判断连通：find(u)==find(v)。

❌ 错误1：find 不写路径压缩 → 树可能退化成链，find O(n)。
→ ✅ return fa[x]==x?x:fa[x]=find(fa[x]);

❌ 错误2：Union 忘记先 find → 直接 fa[a]=b 可能把子树整个挂错位置。
→ ✅ int ra=find(a), rb=find(b); if(ra!=rb) fa[ra]=rb。

Shortest Path

💡 解决什么问题？

带权图中找两点间最短路径。Dijkstra：最快 O((V+E)logV)，但不能有负权边。Floyd：O(V³) 求所有点对。SPFA：可负权但最坏 O(VE) 容易被卡。

📖 Dijkstra 原理

贪心：每次取距离最小的未确定节点（用小根堆维护），用其出边松弛邻居。边权非负保证一旦确定就不会再变小。惰性删除：同节点多次入堆时跳过旧版本（检查 d==dist[u]）。

操作复杂度说明
Dijkstra 堆优化O((V+E)log V)不能处理负权边
Floyd-WarshallO(V³)所有点对，可处理负权
SPFAO(VE) 最坏可负权但容易被卡

🔬 从零开始理解：最短路算法

🎯 生活类比：导航地图

你打开地图导航从 A 到 B，地图告诉你最短路径。背后就是最短路算法。

Dijkstra：边权非负时使用。像水波从起点扩散，每次选当前距离最小的节点确定它的最短距离（贪心），然后更新它的邻居。Floyd：求所有点对之间的最短路，三重循环，dp[k][i][j] 表示"只经过前 k 个点作为中转"时 i 到 j 的最短路。Bellman-Ford / SPFA：可处理负权边。

📐 图解原理

✍️ 手把手做题

核心思想：将所有节点分为"已确定最短距离"和"未确定"两组。每次从未确定组中选dist 最小的节点 u 标记为已确定，然后用 u 的边去松弛它的邻居：if(dist[u]+w < dist[v]) dist[v]=dist[u]+w。

优先队列优化：用 priority_queue（小根堆）维护未确定的节点。每次取堆顶 O(log m)，每条边可能触发一次更新 O(log m)。总复杂度 O(m log m)。稠密图（m≈n²）用朴素 O(n²) 反而更快。

Floyd-Warshall：求所有点对最短路。for(k) for(i) for(j) dp[i][j]=min(dp[i][j], dp[i][k]+dp[k][j])。O(n³)，n≤500 可用。

💡 算法选择：无负权 + 单源→Dijkstra；全源→Floyd(n≤500)；有负权→SPFA/Bellman-Ford。

❌ 错误1：Dijkstra 用于负权图 → 负权边下 Dijkstra 的贪心是错的！
→ ✅ 负权用 SPFA 或 Bellman-Ford。

❌ 错误2：vis 标记位置错误 → 在入队时标记 vis 会导致同一个节点被多次处理。
→ ✅ 在出队时检查 vis，若已确定则跳过。

❌ 错误3：INF 设太小 → 两条 INF 边相加溢出变负数。
→ ✅ INF 设为 0x3f3f3f3f（约 1e9，两倍不溢出）或 1e18。

🔬 从零开始理解：字符串算法

🎯 生活类比：找规律

在长文本中查找一个模式串（如 Ctrl+F 搜索）——这就是字符串匹配。

KMP 算法的核心是next 数组（也叫 failure function）：记录模式串每个位置的最长相等前后缀长度。当匹配失败时，利用已知信息跳过不可能匹配的位置，而不是暴力地每次只移一位。

📐 图解原理

✍️ 手把手做题

场景：在文本 T（长度 n）中查找模式串 P（长度 m）的所有出现位置。

暴力法：每个位置尝试匹配 → O(n*m)，最坏 n=10⁶,m=10⁶ → 10¹² 次操作。

KMP 核心：① 预处理 next 数组：next[i] = P[0..i] 的最长相等前后缀长度（前缀≠整个串）。② 匹配过程：两个指针 i(T)和 j(P)。若 T[i]==P[j] → i++,j++；若失配且 j>0 → j=next[j-1]（利用已知信息跳过）；若失配且 j==0 → i++。

字符串哈希（Rabin-Karp）：把字符串映射成整数（哈希值），O(1) 比较。滚动哈希：hash = (hash * base + s[i]) % mod。用于快速判重、最长回文子串等。

💡 算法选择：单模式匹配→KMP O(n+m)；多模式匹配→AC 自动机；子串判重→字符串哈希。

❌ 错误1：next 数组定义混乱 → 不同教材 next 定义不同（有的存长度，有的存跳转位置）。
→ ✅ 理解本质：next[i] = P[0..i] 最长相等前后缀长度，失配时 j=next[j-1]。

❌ 错误2：字符串哈希只用一种模数 → 可能被卡掉（哈希碰撞）。
→ ✅ 双哈希：用两个不同的 base 和 mod 同时计算，都相等才认为字符串相等。
