链表 (Linked List)

基础

💡 什么是链表？

链表是一种线性数据结构，但与数组不同——它的元素在内存中不连续存储。每个节点包含数据和指向下一个节点的指针。就像一列火车，每节车厢独立存在，通过挂钩连接。插入删除只需改两个指针O(1)，但查找需要从头遍历 O(n)。

📖 数组模拟法 — 竞赛首选

竞赛中用数组模拟链表：e[idx]存数据，ne[idx]存下一节点的下标，head指向头节点。本质是把 Node* next 指针换成了 int ne[i] 下标。预分配数组，比 new/delete 快得多。

操作复杂度说明
头插法 addHead(x)O(1)新节点插入头部，更新 head
指定位置后插入O(1)已知节点位置，改两个指针即可
删除指定节点后一个O(1)跳过被删节点，改指针
遍历链表O(n)从 head 沿 ne 链走到底
查找元素O(n)无随机访问，只能顺序查找
C++
const int N = 1e5 + 5;
int head = -1, e[N], ne[N], idx = 0;
// head=-1 表示空链表
// idx 记录下一个可用的数组位置

// 头插法：在链表头部插入值为 x 的节点
void addHead(int x) {
    e[idx] = x;        // 存数据
    ne[idx] = head;    // 新节点指向原来的头
    head = idx++;      // head 指向新节点
}

// 在第 k 个插入的节点后面插入 x（k 从 0 开始）
void addAfter(int k, int x) {
    e[idx] = x;
    ne[idx] = ne[k];   // 新节点指向 k 的下一个
    ne[k] = idx++;     // k 指向新节点
}

// 删除第 k 个插入的节点后面的节点
void removeAfter(int k) {
    ne[k] = ne[ne[k]]; // 跳过 k 的下一个节点
}

// 遍历链表
for (int i = head; i != -1; i = ne[i])
    cout << e[i] << " ";

// 双向链表扩展：增加 l[N], r[N] 数组存左右邻居
🏆 竞赛口诀： 数组模拟链表 = 把 Node* next 换成 int ne[i]。初始化 head=-1 表示空链表。竞赛中极少用指针链表（慢、易出错），数组模拟是标准写法。

🔬 从零开始理解：链表

🎯 生活类比：火车车厢

链表像一列火车——每节车厢（节点）装载货物（数据），并通过挂钩（指针）连接下一节车厢。车厢散布在车站各处（内存不连续），但通过挂钩串成一列。

插入新车厢只需断开两个挂钩再重新连接，O(1) 搞定。但要找到第 k 节车厢，必须从车头第一节开始一节节往后数，O(n)。

📐 图解原理

✍️ 手把手做题

为什么用数组模拟？竞赛中 new/delete 太慢且容易出错。预分配一个大数组，用 idx 记录下一个可用位置，把指针换成下标。

三个核心变量：e[N]存节点数据，ne[N]存下一节点的下标，head存头节点下标（初始=-1表示空链表），idx存下一个可用的数组位置。

插入操作详解：头插法：① e[idx]=x（存数据）；② ne[idx]=head（新节点指向原头）；③ head=idx++（head 指向新节点）。三步顺序不能乱！

双向链表扩展：增加 l[N], r[N] 分别存左邻居和右邻居的下标。插入时需同时更新四个指针。

💡 适用场景：需要频繁在中间插入/删除的场景（邻接表建图、LRU 缓存、Josephus 问题）。

❌ 错误1：头插法步骤顺序写反 → 如果先改 head，原来 head 指向的节点就丢了。
→ ✅ 正确顺序：存数据→新节点指原头→head指新节点。

❌ 错误2：遍历结束时未判断 -1 → ne[tail] 可能不是 -1，访问越界下标。
→ ✅ for(int i=head; i!=-1; i=ne[i])

❌ 错误3：忘记初始化 head=-1 → head 的初始值是 -1，表示空链表。忘记初始化会导致遍历死循环。

栈 (Stack)

基础

💡 什么是栈？

栈是一种后进先出 (LIFO) 的数据结构——就像一摞盘子，最后放的先拿走。只能从一端（栈顶）操作：push入栈、pop出栈、top看栈顶。函数调用、括号匹配、DFS 都用到栈。

📖 单调栈 — 核心应用

栈内元素保持单调性（递增或递减）。新元素入栈前，把破坏单调性的元素弹出——弹出时就找到了这些元素的答案。典型应用：找每个元素右边第一个比它大的值，O(n)。

操作复杂度说明
push(x)O(1)stk[++top] = x
pop()O(1)top--
top()O(1)返回 stk[top]
单调栈O(n)每个元素入栈出栈各一次
C++
const int N = 1e5 + 5;
int stk[N], tp = 0;  // tp=栈顶指针，0 表示空

void push(int x) { stk[++tp] = x; }  // 入栈
void pop() { tp--; }                  // 出栈
int top() { return stk[tp]; }         // 看栈顶
bool empty() { return tp == 0; }

// ===== 单调栈：找每个元素右边第一个更大值 =====
vector nextGreater(vector& a) {
    int n = a.size(); vector res(n, -1);
    int stk[N], tp = 0;
    for (int i = 0; i < n; i++) {
        // 当前元素比栈顶大 → 栈顶找到了答案
        while (tp && a[stk[tp]] < a[i])
            res[stk[tp--]] = i;  // 或 a[i]
        stk[++tp] = i;  // 下标入栈
    }
    return res;
}
// 单调解法思路：维护递减栈，新元素进来时，
// 所有比它小的栈内元素都找到了"右边第一个更大的"
🏆 竞赛技巧： 推荐用数组模拟栈而非 std::stack——能访问栈内任意元素，调试更方便，速度更快。单调栈每个元素入栈一次出栈一次=O(n)。

🔬 从零开始理解：栈

🎯 生活类比：一摞盘子

你洗好的盘子一个一个往上摞——最后放的先拿（LIFO: Last In First Out）。操作只能在栈顶进行：push（放盘子）、pop（拿盘子）、top（看最上面的盘子）。

函数调用就是栈的典型应用：A 调用 B，B 调用 C——返回时先回到 B 再回到 A。括号匹配、表达式求值、DFS 回溯也都用栈。

📐 图解原理

✍️ 手把手做题

题目：判断一个表达式中的括号是否匹配。如 "(a+b)*(c-d)" 正确，但 "((a+b)" 或 "(a+b))" 错误。

栈解法：遇到左括号 '(' 就 push；遇到右括号 ')' 就 pop。① 如果遇到 ')' 时栈为空→右括号多了；② 遍历完后栈非空→左括号多了。

单调栈核心理解：维护栈内单调性（递增/递减）。新元素入栈前，把所有破坏单调性的元素弹出——弹出时就找到了答案。典型：找每个元素右边第一个比它大的数。

单调栈代码思路：遍历数组，while(栈非空 && a[栈顶] < a[i]) { 栈顶的答案 = i; 弹出; } 然后把 i 入栈。

💡 数组模拟 vs std::stack：推荐数组模拟——能直接访问栈内任意位置，调试方便。

❌ 错误1：出栈前不检查栈是否为空 → 空栈 pop 导致越界。
→ ✅ if(top>0) top--; 或 while 前检查。

❌ 错误2：单调栈维护方向搞反 → 找"右边第一个更大的"应该维护递减栈（栈顶最小）。
→ ✅ 想清楚：是让栈递增还是递减？新元素比栈顶大时弹不弹？

队列 (Queue)

基础

💡 什么是队列？

队列是一种先进先出 (FIFO) 的数据结构——就像排队，先来的先处理。队尾进 (push)，队头出 (pop)。BFS、任务调度都依赖队列。

📖 单调队列 — 滑动窗口神器

维护队列内单调性，队首是窗口最值。两步操作：①去过期（队首滑出窗口就弹出）；②保单调（新元素入队尾前，弹掉比它差的）。滑动窗口最值 O(n)。

操作复杂度说明
push(x)O(1)q[++tt] = x
pop()O(1)hh++
front() / back()O(1)队首 / 队尾
单调队列（滑动窗口）O(n)每个元素进出各一次
C++
const int N = 1e5 + 5;
int q[N], hh = 0, tt = -1;  // hh=队头, tt=队尾

void push(int x) { q[++tt] = x; }  // 入队
void pop() { hh++; }                // 出队
int front() { return q[hh]; }
bool empty() { return hh > tt; }

// ===== 单调队列：滑动窗口最小值 O(n) =====
vector slidingMin(vector& a, int k) {
    int q[N], hh = 0, tt = -1;  // 存下标
    vector res;
    for (int i = 0; i < a.size(); i++) {
        // 第1步：去过期 — 队首滑出窗口
        if (hh <= tt && q[hh] <= i - k) hh++;
        // 第2步：保单调 — 弹掉所有 ≥a[i] 的
        while (hh <= tt && a[q[tt]] >= a[i]) tt--;
        q[++tt] = i;  // 入队
        if (i >= k - 1) res.push_back(a[q[hh]]);
    }
    return res;
}
// 求最大值：把 >= 改成 <= 即可
🏆 单调队列两步走：①去过期（hh 右移）②保单调（tt 左移弹掉更差的）。队首永远是窗口内的最值。

🔬 从零开始理解：队列

🎯 生活类比：排队买奶茶

先来的先买，后来的排后面——这就是队列的 FIFO（First In First Out）原则。队尾进（push），队头出（pop）。

单调队列是更高级的用法：维护队列内的单调性，队首始终是窗口的最值。常用于滑动窗口最大值/最小值问题。

📐 图解原理

✍️ 手把手做题

题目：给定数组和窗口大小 k，窗口从左滑到右，输出每个窗口的最大值。

暴力法：每个窗口遍历 k 个元素找最大值 → O(n*k)，最坏 O(n²)。

单调队列（递减）解法：队首始终是窗口最大值。① 去过期：如果队首下标 ≤ i-k（已滑出窗口）→弹出队首。② 保单调：新元素 a[i] 入队前，弹出队尾所有 ≤ a[i] 的元素（它们永远不可能成为最大值了）。③ 把 i 加入队尾。④ 窗口形成后（i≥k-1），队首 = 当前窗口最大值。

关键理解：为什么可以丢弃比新元素小的？因为新元素在窗口内更靠右、存活更久，且更大，那些又小又老的元素没机会成为最大值。

💡 与单调栈区别：单调栈处理"找更大/更小元素"；单调队列处理"滑动窗口最值"。

❌ 错误1：队列数组开太小 → 用数组模拟队列时 hh 和 tt 都会一直增长，可能超过 N。
→ ✅ 开 N+5 大小，或者用循环队列 hh%N。

❌ 错误2：忘记去过期元素 → 队首可能已经滑出窗口，造成错误答案。
→ ✅ 每次循环先检查队首是否过期。

二叉树 (Binary Tree)

基础

💡 什么是二叉树？

每个节点最多有两个子节点（左/右）。二叉树是所有树形结构的基础——堆、线段树、Trie、BST 都是它的变体。存储方式有链式（指针）和顺序存储（数组，i的左子=2i，右子=2i+1）。

📖 四种遍历

前序（根→左→右）：用于复制树。中序（左→根→右）：BST 有序输出。后序（左→右→根）：删除树。层序（BFS）：广度优先。已知中序+前序/后序可唯一确定一棵树。

操作复杂度说明
前序遍历O(n)根→左→右（递归/栈）
中序遍历O(n)左→根→右（BST 有序）
后序遍历O(n)左→右→根（删除用）
层序遍历O(n)BFS 队列实现
前序+中序构造树O(n)前序第一个是根，中序定位左右
C++
struct TreeNode {
    int val;
    TreeNode *left, *right;
    TreeNode(int x) : val(x), left(nullptr), right(nullptr) {}
};

// 前序：根→左→右
void preorder(TreeNode* r) {
    if (!r) return;
    cout << r->val; preorder(r->left); preorder(r->right);
}
// 中序：左→根→右
void inorder(TreeNode* r) {
    if (!r) return;
    inorder(r->left); cout << r->val; inorder(r->right);
}
// 后序：左→右→根
void postorder(TreeNode* r) {
    if (!r) return;
    postorder(r->left); postorder(r->right); cout << r->val;
}

// 已知前序+中序，构造二叉树 O(n)
TreeNode* build(vector& pre, vector& in,
                int pl, int pr, int il, int ir) {
    if (pl > pr) return nullptr;
    int rootVal = pre[pl];  // 前序第一个 = 根
    // 在中序中找到根的位置
    int k = find(in.begin()+il, in.begin()+ir+1, rootVal) - in.begin();
    TreeNode* root = new TreeNode(rootVal);
    int leftSize = k - il;
    // 递归构造左右子树
    root->left  = build(pre, in, pl+1, pl+leftSize, il, k-1);
    root->right = build(pre, in, pl+leftSize+1, pr, k+1, ir);
    return root;
}
🏆 关键理解： 前序第一个=根；中序中根左边=左子树，右边=右子树。递归应用即得整棵树。前序+后序不能唯一确定（无法区分左右）。

🔬 从零开始理解：二叉树

🎯 生活类比：家族族谱

二叉树每个节点最多有两个孩子：左孩子和右孩子。像一棵倒挂的树：根在上面，叶子在下面。

遍历方式三种：① 前序（根→左→右）：先访问根，再递归左子树、右子树。② 中序（左→根→右）：对二叉搜索树会得到有序序列！③ 后序（左→右→根）：自底向上处理信息（如求子树大小）。

📐 图解原理

✍️ 手把手做题

题目：给定一棵树，求树上最远两个节点之间的距离（树的直径）。

解法：两次 DFS：① 从任意节点 a 出发 DFS，找到距离 a 最远的节点 u。② 从 u 出发再 DFS，找到距离 u 最远的节点 v。u 到 v 的距离就是树的直径。

证明思路：反证法。如果直径不是 u-v，则可以构造一条更长的路径，矛盾。这个证明不要求掌握，但要知道这个算法是对的。

二叉树存储方式：① 链式存储：struct Node{int val; Node *left,*right;}；② 数组存储（竞赛常用）：l[i], r[i] 存左右孩子下标。③ 完全二叉树：节点 i 的左孩子 2i+1，右孩子 2i+2。

💡 记忆口诀：前序=根左右；中序=左根右（BST有序）；后序=左右根。递归实现 3 行代码。

❌ 错误1：遍历时忘记判断空节点 → 访问 NULL 指针或越界下标导致 RE。
→ ✅ if(root==nullptr) return; 或 if(u==-1) return;

❌ 错误2：中序遍历结果不唯一决定树结构 → 仅凭中序无法还原树！需要前序+中序或后序+中序才能唯一确定。

堆 (Heap)

进阶

💡 什么是堆？

堆是一种完全二叉树，满足堆性质：每个节点 ≤ 子节点（小根堆）或 ≥ 子节点（大根堆）。数组存储，i 的左子=2i，右子=2i+1，父=i/2。取最值 O(1)，插入/删除 O(log n)。

📖 up 上浮 vs down 下沉

插入：新元素放末尾→与父节点比较→如果更小就交换（up 上浮）。删堆顶：最后元素搬到堆顶→与较小儿子比较→如果更大就交换（down 下沉）。每次交换上升/下沉一层，最多 log n 层。

操作复杂度说明
push(x) 插入O(log n)末尾插入 + up 上浮
pop() 删堆顶O(log n)最后元素替堆顶 + down 下沉
top() 取堆顶O(1)直接返回 heap[1]
build() 建堆O(n)从 n/2 到 1 逐个 down（比逐个插入 O(n log n) 更快）
C++
const int N = 1e5 + 5;
int heap[N], sz = 0;  // sz = 堆大小

// 上浮：从位置 u 向上调整（插入时用）
void up(int u) {
    while (u > 1 && heap[u] < heap[u >> 1]) {
        swap(heap[u], heap[u >> 1]);
        u >>= 1;  // u = u/2，跳到父节点
    }
}
// 下沉：从位置 u 向下调整（删除时用）
void down(int u) {
    int t = u;
    if (u*2 <= sz && heap[u*2] < heap[t]) t = u*2;
    if (u*2+1 <= sz && heap[u*2+1] < heap[t]) t = u*2+1;
    if (t != u) { swap(heap[u], heap[t]); down(t); }
}
void push(int x) { heap[++sz] = x; up(sz); }   // 插入
void pop() { heap[1] = heap[sz--]; down(1); }  // 删堆顶
int top() { return heap[1]; }                   // 取堆顶
// O(n) 建堆：从最后一个非叶节点开始逐个 down
void build() { for (int i = sz/2; i; i--) down(i); }

// 对顶堆：维护中位数
// 大根堆(左半) + 小根堆(右半)，平衡两堆大小
🏆 手写堆 vs STL： priority_queue 只能取堆顶，不能修改内部元素。手写堆可以修改任意位置并重新 up/down——Dijkstra 的惰性删除就可以用手写堆优化。

🔬 从零开始理解：堆

🎯 生活类比：急诊室分诊

急诊室不是先来先看——病情最紧急的患者优先。堆就是一种优先级队列，始终能快速获取最值（最小堆的堆顶是最小值，最大堆堆顶是最大值）。

堆是一棵完全二叉树，满足堆性质：每个节点 ≤ 它的孩子（最小堆）。插入和删除堆顶都是 O(log n)。

📐 图解原理

✍️ 手把手做题

堆排序：① 建堆 O(n)（从最后一个非叶节点开始向下调整）；② 依次取出堆顶 O(n log n)。原地排序，不稳定。

Top-K 问题：找最大的 K 个数。用大小为 K 的最小堆：遍历所有元素，堆不满时直接入堆；堆满时若元素 > 堆顶 → 弹出堆顶、插入新元素。复杂度 O(n log k)。

堆的核心操作：① 上浮 (up/swim)：新元素插入堆底，若比父节点小则交换，递归向上直到满足堆性质。② 下沉 (down/sink)：堆顶被替换后，和较小的孩子交换，递归向下直到满足堆性质。

💡 竞赛建议：直接用 std::priority_queue（默认最大堆）。最小堆用 priority_queue。

❌ 错误1：建堆写成 O(n log n) → 逐个插入建堆 O(n log n)，但直接对数组 heapify 是 O(n)。
→ ✅ 从 n/2 到 0 依次 down(i) 即可 O(n) 建堆。

❌ 错误2：向上/向下调整时下标计算错误 → 左孩子 = 2*i+1（不是 2*i），父 = (i-1)/2。
→ ✅ 0-indexed 确认下标公式。

哈希表 (Hash Table)

进阶

💡 什么是哈希表？

把任意类型的数据映射到数组下标，实现 O(1) 均摊的增删查。核心挑战是冲突——不同数据可能映射到同一位置。两种处理方式：拉链法（每个槽挂链表）和开放寻址法（冲突时往后找空位）。

📖 为什么 N 要取质数？

如果 N=10，所有以 0 结尾的 key 都映射到同一位——分布不均。质数作为模数可以避免这种周期性冲突。常用质数：100003, 200003, 300007。开放寻址法需要 N 为数据量的 2~3 倍。

操作复杂度说明
插入 (开放寻址)O(1) 均摊找空位插入，冲突时线性探查
查找 (开放寻址)O(1) 均摊探查直到找到或遇空位
插入 (拉链法)O(1) 均摊头插法挂到对应槽的链表
字符串哈希O(n) 预处理 / O(1) 比较子串比较从 O(n) 变 O(1)
C++
// ===== 开放寻址法（推荐，缓存友好）=====
const int N = 200003;  // 质数，2~3 倍空间
const int INF = 0x3f3f3f3f;
int h[N];
memset(h, 0x3f, sizeof h);  // 初始化为 INF 表示空

// find：找到 x 应该存的位置（或已存的位置）
int find(int x) {
    int k = (x % N + N) % N;  // 处理负数取模
    while (h[k] != INF && h[k] != x) {
        k++;           // 线性探查
        if (k == N) k = 0;  // 循环
    }
    return k;
}
void insert(int x) { h[find(x)] = x; }
bool contains(int x) { return h[find(x)] == x; }

// ===== 字符串哈希：O(1) 比较任意子串 =====
typedef unsigned long long ull;
const ull BASE = 131;  // 131 或 13331
ull hsh[N], p[N];
void init(string& s) {
    int n = s.size(); p[0] = 1;
    for (int i = 0; i < n; i++) {
        hsh[i+1] = hsh[i] * BASE + s[i];
        p[i+1] = p[i] * BASE;
    }
}
ull getHash(int l, int r) {  // [l, r] 的哈希值
    return hsh[r+1] - hsh[l] * p[r-l+1];
}
🏆 选择建议： 日常刷题用 unordered_map（加防卡哈希）；手写时用开放寻址法（比拉链法更快）。字符串哈希简单实用，应优先掌握。

🔬 从零开始理解：哈希表

🎯 生活类比：图书馆索书号

每本书有一个唯一的索书号（键），通过索书号你可以 O(1) 快速找到书的位置。这个"索书号→书架位置"的映射就是哈希表。

核心操作：hash(key) → 数组下标。可能出现哈希冲突（两个 key 映射到同一位置），解决方案：① 拉链法：每个位置存一个链表；② 开放寻址法：冲突就往后找空位。

📐 图解原理

✍️ 手把手做题

题目（LeetCode 1）：给定数组和目标值 target，找两个数使得它们的和等于 target。

暴力法：两重循环 O(n²)。哈希表优化：遍历数组，对于 a[i]，看看 target - a[i] 是否已经出现过（在哈希表中）。若出现过→找到答案；若没有→把 a[i] 及其下标存入哈希表。O(n)！

哈希的核心价值：把"查找"从 O(n) 降到 O(1)。很多题目的暴力解法是两重循环，用哈希表优化后变成一次遍历。

竞赛技巧：能排序时用 map（O(log n)，有序）；查找为主时用 unordered_map（O(1)，但可能被卡）。自定义哈希函数可防止被出题人卡掉。

💡 应用场景：快速查找、去重、计数、两数之和类问题、字符频率统计。

❌ 错误1：用自定义结构体做 key 忘记写哈希函数 → pair/unordered_map 默认不支持 pair 做 key。
→ ✅ 需自定义 hash 结构体，或用 map（支持 pair 比较）。

❌ 错误2：哈希冲突导致退化 → 竞赛中可能被故意构造冲突数据使 unordered_map 退化到 O(n)。
→ ✅ 使用自定义哈希函数、或改用 map（稳定 O(log n)）、或 C++20 的 flat_map。

并查集 (DSU)

核心

💡 什么是并查集？

处理集合合并与查询的数据结构。"A和B在同一集合吗？""把这两个集合合并"。每个元素指向父节点，根节点代表整个集合。合并时只需把一棵树的根指向另一棵。

📖 路径压缩 + 按秩合并

路径压缩：find 时把路径上所有节点直连到根，以后查找 O(1)。按秩合并：小树并入大树，保持树高 O(log n)。双优化后均摊 ≈O(α(n))≈O(4)≈常数！

操作复杂度说明
find(x)O(α(n)) ≈ O(1)找根 + 路径压缩
unite(x,y)O(α(n)) ≈ O(1)合并两集合，按秩合并
same(x,y)O(α(n)) ≈ O(1)判断是否同集合
扩展域 / 带权 DSUO(α(n))处理对立关系 / 维护距离
C++
struct DSU {
    vector fa, sz;
    DSU(int n) : fa(n + 1), sz(n + 1, 1) {
        iota(fa.begin(), fa.end(), 0);  // 初始：每个元素独立
    }
    int find(int x) {
        // 路径压缩：找到根后顺手把路径上所有节点直连根
        return fa[x] == x ? x : fa[x] = find(fa[x]);
    }
    bool unite(int x, int y) {
        x = find(x), y = find(y);
        if (x == y) return false;  // 已在同集合
        if (sz[x] < sz[y]) swap(x, y);  // 小树并入大树
        fa[y] = x; sz[x] += sz[y];
        return true;
    }
    bool same(int x, int y) { return find(x) == find(y); }
    int size(int x) { return sz[find(x)]; }
};

// 扩展域（种类并查集）：x 和 x+n 表示对立关系
// DSU dsu(2*n); dsu.unite(x, y+n); 表示 x 和 y 是敌人
🏆 核心理解： find 里的 fa[x]=find(fa[x]) 既是递归找根又是路径压缩，是并查集的灵魂。Kruskal 最小生成树、连通性判断都依赖它。

🔬 从零开始理解：并查集

🎯 生活类比：家族合并

起初每个人自己是一家之主。后来有人告诉你"A 和 B 是一家人"——于是两个家族合并。如何快速判断"X 和 Y 是不是一家人"？

并查集维护等价关系：① Find：找某个人的"族长"（一路向上找到根）。② Union：把两个家族合并（一个族长认另一个族长做父）。加上路径压缩和按秩合并，操作几乎是 O(1)。

📐 图解原理

✍️ 手把手做题

题目：有 n 个点，初始没有边。每次加一条边 (u, v)，问当前有多少个连通块。

DSU 解法：① 初始：fa[i]=i, 连通块数=n。② 加边 (u,v)：int ru=find(u), rv=find(v); if(ru!=rv) { fa[ru]=rv; 连通块数--; }。如果 ru==rv 说明已连通，这条边是多余的（会形成环）。

一行 find（路径压缩）：int find(int x){return fa[x]==x ? x : fa[x]=find(fa[x]);} — 递归的同时把路径上所有节点直接接在根上。

💡 应用场景：连通块计数、Kruskal 最小生成树、朋友圈/亲戚关系、动态连通性判断、判环。

❌ 错误1：find 不写路径压缩 → 树可能退化成链，单次 find O(n)，n 次 O(n²)。
→ ✅ 必须写 fa[x]=find(fa[x])，不能只 return find(fa[x])。

❌ 错误2：Union 时直接 fa[a]=b 不做 find → 可能把子树挂错位置。
→ ✅ 必须先 int ra=find(a), rb=find(b)，再 fa[ra]=rb。

❌ 错误3：忘记初始化 fa[i]=i → 每个元素初始时指向自己（自己是自己的根）。

树状数组 (BIT)

进阶

💡 为什么需要树状数组？

数组：单点修改 O(1) 但区间和 O(n)。前缀和：区间和 O(1) 但单点修改 O(n)。树状数组两者都是 O(log n)！代码不到 10 行，是最简洁的区间查询结构。核心是 lowbit。

📖 lowbit 原理

lowbit(x) = x & -x 取出 x 的最低位 1。tr[x] 管理 a[x-lowbit(x)+1 .. x] 这个区间。add：沿 lowbit 往上跳更新所有包含 x 的区间。sum：沿 lowbit 往下跳累加前缀和。

操作复杂度说明
add(x, c)O(log n)a[x] += c，沿 lowbit 往上更新
sum(x)O(log n)查前缀和 a[1..x]，沿 lowbit 往下
rangeSum(l,r)O(log n)sum(r) - sum(l-1)
差分 BITO(log n)区间加 + 单点查
C++
const int N = 1e5 + 5;
int tr[N], n;  // 树状数组，1-indexed

int lowbit(int x) { return x & -x; }  // 取最低位1

// 单点修改：a[x] += c，向上更新
void add(int x, int c) {
    for (int i = x; i <= n; i += lowbit(i))
        tr[i] += c;
}
// 前缀查询：a[1] + a[2] + ... + a[x]
int sum(int x) {
    int res = 0;
    for (int i = x; i; i -= lowbit(i))
        res += tr[i];
    return res;
}
int rangeSum(int l, int r) { return sum(r) - sum(l - 1); }

// ===== 差分 BIT：区间加 + 单点查 =====
// add(l, x); add(r+1, -x);  查x的值：sum(x)

// 核心图解：
// sum(7): 7→6→4→0 (每次减 lowbit，O(log n)步)
// add(3): 3→4→8→... (每次加 lowbit，O(log n)步)
🏆 口诀： sum 往下跳（减 lowbit），add 往上跳（加 lowbit）。BIT 是线段树的轻量替代——能用 BIT 的场合优先用 BIT。

🔬 从零开始理解：树状数组 (Fenwick Tree)

🎯 生活类比：分组管理

你管理一个团队，每个人有自己的业绩。老板经常问"第 1 到第 k 个人总业绩多少？"你需要快速回答。树状数组的巧妙之处：用二进制的 lowbit 来分组——每个位置 i 存储 i 往前 lowbit(i) 个元素的和。

更新一个位置的值 = 沿着树往上更新所有"管辖"它的节点。查询前缀和 = 沿着树往下累加。两步都是 O(log n)，代码极其简洁。

📐 图解原理

✍️ 手把手做题

BIT vs 前缀和：前缀和可以 O(1) 查询但修改是 O(n)；BIT 查询和修改都是 O(log n)，适合动态修改+查询的场景。

三个核心函数（背下来！）：① lowbit(x) = x & -x（x 的二进制最低位 1）；② add(i, v)：while(i≤n) c[i]+=v, i+=lowbit(i)；③ sum(i)：while(i>0) ans+=c[i], i-=lowbit(i)。

区间修改+单点查询：用差分 BIT。区间 [l,r]+v → add(l,v), add(r+1,-v)。查询点 x → sum(x)。

区间修改+区间查询：需要两个 BIT，维护差分数组和 i*差分[i] 的前缀和。

💡 适用场景：比线段树代码量少得多！能用 BIT 就不用线段树。求逆序对、求区间和（带修改）、二维偏序。

❌ 错误1：BIT 下标从 0 开始 → BIT 必须从 1 开始！lowbit(0)=0 会导致死循环。
→ ✅ 所有输入下标 +1 转换为 1-indexed。

❌ 错误2：把 BIT 当线段树用 → BIT 只能维护前缀信息（和、最大值等可减/可合并的信息）。不能直接维护区间最值（需扩展）。

线段树 (Segment Tree)

高级

💡 为什么需要线段树？

BIT 只能做前缀和类操作。线段树支持区间修改 + 任意区间查询（和、最值、GCD 等）。核心是懒标记 (Lazy Tag)：修改时不递归到底，只在节点上"记账"，查询时再下传——O(log n)。

📖 三个核心操作

pushup：用子节点更新父节点（修改完子节点后调用）。pushdown：把懒标记下传给子节点（进入子节点前调用）。modify/query：完全包含→直接操作；否则→pushdown→递归→pushup。

操作复杂度说明
build()O(n)建树，从根递归构造
modify(l,r,v)O(log n)区间修改+懒标记
query(l,r)O(log n)区间查询，路过时 pushdown
空间复杂度O(4n)必须开 4 倍数组！
C++
typedef long long ll;
const int N = 1e5 + 5;
struct Node { int l, r; ll sum, add; } tr[N * 4]; // 4倍！
int a[N];

void pushup(int u) { tr[u].sum = tr[u<<1].sum + tr[u<<1|1].sum; }

void pushdown(int u) {  // 懒标记下传
    auto &rt = tr[u], &L = tr[u<<1], &R = tr[u<<1|1];
    if (rt.add) {
        L.add += rt.add; L.sum += (L.r - L.l + 1) * rt.add;
        R.add += rt.add; R.sum += (R.r - R.l + 1) * rt.add;
        rt.add = 0;  // 清空当前标记
    }
}
void build(int u, int l, int r) {
    tr[u] = {l, r};
    if (l == r) { tr[u].sum = a[l]; return; }
    int mid = (l + r) >> 1;
    build(u<<1, l, mid); build(u<<1|1, mid+1, r);
    pushup(u);
}
void modify(int u, int l, int r, int v) {
    if (tr[u].l >= l && tr[u].r <= r) {  // 完全包含
        tr[u].sum += (tr[u].r - tr[u].l + 1) * v;
        tr[u].add += v; return;  // 打标记，不往下
    }
    pushdown(u);  // 进入子节点前必须下传！
    int mid = (tr[u].l + tr[u].r) >> 1;
    if (l <= mid) modify(u<<1, l, r, v);
    if (r > mid) modify(u<<1|1, l, r, v);
    pushup(u);
}
ll query(int u, int l, int r) {
    if (tr[u].l >= l && tr[u].r <= r) return tr[u].sum;
    pushdown(u);
    int mid = (tr[u].l + tr[u].r) >> 1; ll res = 0;
    if (l <= mid) res += query(u<<1, l, r);
    if (r > mid) res += query(u<<1|1, l, r);
    return res;
}
⚠️ 三大易错： ① 开 4 倍空间！② 进入子节点前必须 pushdown！③ 从子节点返回后必须 pushup！这三个缺一个就错。

🔬 从零开始理解：线段树

🎯 生活类比：部门汇报系统

CEO 需要知道"第 3 到第 8 个部门的总业绩"，每个部门经理随时可能更新业绩。如果每个人都直接向 CEO 汇报→CEO 被信息淹没。线段树的方案：分层管理——小组长汇总 2 个部门，经理汇总 4 个部门，总监汇总 8 个部门...每个节点汇总它管辖范围的信息，查询和更新都只需 O(log n)。

📐 图解原理

✍️ 手把手做题

问题：两种操作：① 单点修改 a[pos]+=v；② 查询区间 [l, r] 的和。n, q ≤ 10⁵。

线段树结构：① build：递归建树，叶子节点 = a[i]，内部节点 = 左孩子 + 右孩子。② update：从根往下找到叶子，更新后向上重新汇总（pushup）。③ query：若当前区间完全在查询区间内→直接返回；若完全不相交→return 0；否则分别查询左右孩子。

懒标记（Lazy Tag）：区间修改时用到。不立刻更新所有叶子，而是在节点上打一个"待办"标记，查询/修改路过时再往下传（pushdown）。

💡 BIT vs 线段树：BIT 代码量少但只能做前缀信息；线段树更通用（区间最值、区间修改、动态开点、可持久化...）。能用 BIT 优先 BIT，否则上线段树。

❌ 错误1：数组开太小 → 线段树最多需要 4n 个节点（不是 2n！）。
→ ✅ 习惯开 4*N+5。

❌ 错误2：懒标记忘记 pushdown → 查询/修改孩子前必须先 pushdown，否则用到过期数据。
→ ✅ 每次进入递归前 if(l

❌ 错误3：区间查询时漏判不相交的情况 → 如果当前区间完全在查询区间外，直接 return 0（求和）或 -INF（最值）。

字典树 (Trie)

进阶

💡 什么是 Trie？

又称前缀树，用于大量字符串的高效检索。每个节点有 26 个子节点（对应 a-z）。从根到某节点的路径就是一个字符串。插入/查询 O(L)，L 为字符串长度，与数据总量无关。

📖 01-Trie：求最大异或

每个节点只有 0/1 两条边。将数字二进制拆分（32位）插入 Trie。查询最大异或时优先走相反位——因为异或相同=0、不同=1，高位相反贡献更大。O(n×32)。

操作复杂度说明
insert(s)O(L)逐字符走 Trie 树，L=字符串长度
query(s)O(L)查询 s 是否出现过 / 出现次数
01-Trie 插入O(32)数字拆成二进制逐位插入
01-Trie 最大异或O(32)每位优先走相反位
C++
// ===== 字典树 =====
const int N = 1e5 + 5;  // 总字符数
int son[N][26], cnt[N], idx = 0;
// son[p][c] = 节点 p 经过字符 c 到达的子节点

void insert(string& s) {
    int p = 0;  // 从根开始
    for (char c : s) {
        int u = c - 'a';
        if (!son[p][u]) son[p][u] = ++idx;  // 创建新节点
        p = son[p][u];
    }
    cnt[p]++;  // 以该节点结尾的单词数+1
}
int query(string& s) {  // 查询 s 出现次数
    int p = 0;
    for (char c : s) {
        int u = c - 'a';
        if (!son[p][u]) return 0;  // 不存在
        p = son[p][u];
    }
    return cnt[p];
}

// ===== 01-Trie：求数组中两个数的最大异或值 =====
const int M = N * 31;  // 每个数最多31位
int son2[M][2], idx2 = 0;
void insert(int x) {
    int p = 0;
    for (int i = 30; i >= 0; i--) {  // 从高位到低位
        int u = (x >> i) & 1;
        if (!son2[p][u]) son2[p][u] = ++idx2;
        p = son2[p][u];
    }
}
int maxXor(int x) {  // 查询与 x 异或的最大值
    int p = 0, res = 0;
    for (int i = 30; i >= 0; i--) {
        int u = (x >> i) & 1;
        // 优先走相反位（异或=1 贡献大）
        if (son2[p][!u]) { res |= (1 << i); p = son2[p][!u]; }
        else p = son2[p][u];
    }
    return res;
}
🏆 理解关键： Trie 用空间换时间，把字符串公共前缀合并存储。01-Trie 的"优先走相反位"是贪心思想——高位差异越大异或值越大。

🔬 从零开始理解：字典树 (Trie)

🎯 生活类比：手机输入法联想

你在手机输入"hel"，输入法弹出 help、hello、helm... 这是怎么做到的？背后很可能是字典树 (Trie)：把每个单词的每个字符作为一个节点，公共前缀共享路径。查找一个单词只需 O(len) 时间。

每个节点有两个关键信息：① 孩子指针（26个字母或 son[p][c]）；② 结束标记（这个节点是不是某个单词的结尾）。

📐 图解原理

✍️ 手把手做题

题目（AcWing 143）：在 N 个整数中选两个数做异或运算，结果最大是多少？

暴力法：两重循环枚举 O(n²)，n=10⁵ 时必超时。

Trie 优化（O(32n)）：① 把每个数的二进制位（32位）插入 Trie（每层 0/1 两个分支）。② 对于每个数，在 Trie 中尽量走相反的位（1→走0，0→走1），这样异或结果最大。③ 本质：把异或求最值变成了"树上贪心搜索"。

为什么用 Trie？Trie 天然支持按位查找，这是哈希表做不到的。Trie 在处理字符串前缀/二进制位/字典序问题时无可替代。

💡 应用场景：单词查找、前缀匹配、自动补全、最大异或和、字符串频次统计。

❌ 错误1：忘记初始化 Trie 节点 → 新增节点时必须 memset(son[idx], 0, sizeof(son[idx]))。
→ ✅ 每次创建新节点时清零。

❌ 错误2：Trie 数组开太小 → 插入 n 个长度为 m 的字符串需要 n*m 个节点。
→ ✅ 根据题目数据范围估算节点总数。

图的存储

基础

💡 图是什么？

图由顶点和边组成——社交网络、交通路网、依赖关系都是图。三种存储方式各有适用场景：邻接矩阵（稠密图）、邻接表（最常用）、链式前向星（最快）。

📖 链式前向星原理

每条边有唯一编号 idx。h[u] 存 u 的最后一条边的编号，ne[i] 串起前面的边。遍历 u 的边：for(i=h[u]; ~i; i=ne[i])。本质是数组模拟的邻接表，比 vector 更快更省内存。

操作复杂度说明
邻接表 vectorO(V+E) 空间最常用，灵活方便
链式前向星O(V+E) 空间最快，边有编号，卡常必备
邻接矩阵O(V²) 空间n≤2000 稠密图，Floyd 用
Floyd 多源最短路O(V³)配合邻接矩阵使用
C++
// ===== 1. 邻接表 — 最常用 =====
vector> g(n + 1);
// 加边
g[u].push_back(v);          // 有向边
g[u].push_back(v); g[v].push_back(u); // 无向边
// 带权边
vector>> gw(n + 1);
gw[u].push_back({v, w});

// ===== 2. 链式前向星 — 最快 =====
const int N = 1e5+5, M = 2e5+5;
int h[N], e[M], ne[M], w[M], idx;
memset(h, -1, sizeof h);  // -1 表示空
void add(int u, int v, int wt) {  // 加边 u→v 权 wt
    e[idx] = v; w[idx] = wt;
    ne[idx] = h[u]; h[u] = idx++;
}
// 遍历 u 的所有出边
for (int i = h[u]; i != -1; i = ne[i]) {
    int v = e[i], weight = w[i];  // 邻接点v，边权weight
}

// ===== 3. 邻接矩阵 =====
int g2[1005][1005];
memset(g2, 0x3f, sizeof g2);  // 初始化为无穷大
for (int i = 1; i <= n; i++) g2[i][i] = 0;
g2[u][v] = min(g2[u][v], w);  // 加边
🏆 选择建议： 日常刷题用 vector 邻接表（最简单）。需要卡常优化时换链式前向星。n≤500 的稠密图用邻接矩阵。

🔬 从零开始理解：图的存储

🎯 生活类比：城市交通图

城市是节点（顶点），公路是边。如何把这张"关系图"存进计算机？三种主要方式：

① 邻接矩阵：二维数组 g[u][v]，存得下 n≤5000 的稠密图。② 邻接表（链式前向星）：竞赛最常用！每个节点挂一条链表存它的邻居。③ 边列表：Kruskal 算法专用。

📐 图解原理

✍️ 手把手做题

如何选择存储方式？

  • 邻接矩阵 g[u][v]：简单暴力，O(n²) 空间，适合 n≤5000 的稠密图（边接近 n²）。
  • 邻接表（链式前向星）：竞赛首选！O(n+m) 空间，加边 O(1)。用数组模拟：h[u] 存 u 的第一条边下标，e[i] 存目标节点，ne[i] 存下一条边，w[i] 存权重。
  • 边列表：单纯存所有边 (u, v, w)，用于 Kruskal 最小生成树。

DFS 遍历图：for(int i=h[u]; ~i; i=ne[i]) { int v=e[i]; if(!vis[v]) dfs(v); } — 注意图和树的区别：图可能有环，必须用 vis 数组防止重复访问。

💡 竞赛习惯：链式前向星几乎万能，99% 的图论题用它存图。

❌ 错误1：邻接表头指针忘记初始化为 -1 → memset(h, -1, sizeof h)。否则 h[a] 可能存随机值，遍历时访问越界。

❌ 错误2：无向图只加一条边 → 无向图需要 add(a,b,w); add(b,a,w); 加两次！
→ ✅ 边数组 e[M], ne[M] 要开 2*M（无向图每条边存两次）。

❌ 错误3：遍历图忘记标记 vis → 图有环时会无限递归，导致 MLE/TLE。
